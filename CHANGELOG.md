# Changelog

## 0.3.2 (2026-10-15)

before this, the subcommand contract stopped at the first error, so one bad field hid everything after it. now it collects: every field, every init_required flag field and every validation rule gets checked, the errors go into one SynBuffer, and it hard fails once at the end with all of them. also in here: _skipping versions of the two contract emitters for a derive that already reported some fields, a fix for the r#type panic in composite surfaces, and CI that tests on stable and 1.85 and publishes from main.

### the collector (src/subcommand.rs)

- setters and argv pushes were each a `.collect::<syn::Result<Vec<_>>>()?`, then a `?` on the constructor and another on the validated command impl, so the first bad field returned and nothing after it got looked at: [src/subcommand.rs L86-L98](https://github.com/jameshuntt/simple_impl_quote_kit/blob/61511c0fbfac6b3b3238c1c6c9988c42d6bab241/src/subcommand.rs#L86-L98). now it's one field loop feeding a SynBuffer through `errs.absorb(...)`, and `errs.finish()?` after the validated command impl is the one hard fail: [src/subcommand.rs L101-L114](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/subcommand.rs#L101-L114). SynBuffer comes from liaise_proc_macro 0.1.3: [liaise_proc_macro src/lib.rs L187-L192](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L187-L192), and so do absorb and finish: [liaise_proc_macro src/lib.rs L221-L242](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L221-L242).
- the setter and the argv push do the same bool check on a flag field with the same message: [src/setters.rs L11-L17](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/setters.rs#L11-L17), [src/argv.rs L10-L16](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/argv.rs#L10-L16). with collecting, a non-bool flag field would put that error in the buffer twice, so the loop only asks for the argv push when the setter worked: [src/subcommand.rs L104-L110](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/subcommand.rs#L104-L110).
- the init_required check returned on the first init_required field that was a flag: [src/subcommand.rs L129-L136](https://github.com/jameshuntt/simple_impl_quote_kit/blob/61511c0fbfac6b3b3238c1c6c9988c42d6bab241/src/subcommand.rs#L129-L136). now each one gets pushed and it finishes after the loop, so every one is reported: [src/subcommand.rs L145-L154](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/subcommand.rs#L145-L154).

### validation rules (src/validation.rs)

- the rule list was a `.collect::<syn::Result<Vec<_>>>()?`, so the first rule with a bad name stopped the rest from being checked: [src/validation.rs L22-L26](https://github.com/jameshuntt/simple_impl_quote_kit/blob/61511c0fbfac6b3b3238c1c6c9988c42d6bab241/src/validation.rs#L22-L26). now it's `collect_all` over every rule: [src/validation.rs L37-L40](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L37-L40). collect_all is the collecting form of that collect, from liaise_proc_macro: [liaise_proc_macro src/lib.rs L178-L185](https://github.com/jameshuntt/liaise_proc_macro/blob/98d133c891db2de0e4f44a2d0f789b616fc3e862/src/lib.rs#L178-L185).
- inside a rule each name was `active_expr(...)?`, so a rule with two unknown names only reported the first one: [src/validation.rs L53-L54](https://github.com/jameshuntt/simple_impl_quote_kit/blob/61511c0fbfac6b3b3238c1c6c9988c42d6bab241/src/validation.rs#L53-L54), and one_of and at_least_one_of stopped the same way: [src/validation.rs L113-L116](https://github.com/jameshuntt/simple_impl_quote_kit/blob/61511c0fbfac6b3b3238c1c6c9988c42d6bab241/src/validation.rs#L113-L116), [src/validation.rs L136-L139](https://github.com/jameshuntt/simple_impl_quote_kit/blob/61511c0fbfac6b3b3238c1c6c9988c42d6bab241/src/validation.rs#L136-L139). now both names of requires, invalid_without, only_pair_with and conflicts_with go through collect_all: [src/validation.rs L99-L101](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L99-L101) (same shape at L115, L131, L147), and so does every name in one_of / at_least_one_of: [src/validation.rs L163](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L163-L163), [src/validation.rs L183](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L183-L183).
- the unknown field error only named the field, not the rule: [src/validation.rs L170-L173](https://github.com/jameshuntt/simple_impl_quote_kit/blob/61511c0fbfac6b3b3238c1c6c9988c42d6bab241/src/validation.rs#L170-L173). with collecting, two rules naming the same missing field could print the same message and you couldn't tell which rule it came from. now every error out of a rule gets `: in <rule>` on the end, like "validation rule references unknown field `b`: in #[requires] on `a`": [src/validation.rs L61-L77](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L61-L77). the default wording per rule is rule_context: [src/validation.rs L79-L90](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L79-L90).

### the _skipping emitters

- new `emit_validated_command_impl_skipping(spec, skipped, rule_contexts)`, for a derive that already reported some fields and left them out of the spec: [src/validation.rs L24-L34](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L24-L34). a rule naming a skipped field is still checked for its other names. the skipped one comes back as `false` with no error, so it isn't reported a second time: [src/validation.rs L208-L212](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L208-L212). `rule_contexts[i]`, when given, replaces the rule_context wording, so the caller can show the rule as written before it dropped the bad names: [src/validation.rs L27-L28](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L27-L28), [src/validation.rs L38](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L38-L38).
- new `emit_simple_subcommand_contract_impls_skipping(spec, skipped, rule_contexts)`, same idea for the whole contract. it passes skipped and rule_contexts down to the validation side, and its tokens only mean anything when skipped is empty: [src/subcommand.rs L85-L95](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/subcommand.rs#L85-L95), [src/subcommand.rs L113](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/subcommand.rs#L113-L113).
- the existing two keep their signatures and just call the _skipping versions with empty slices, so they collect the same way: [src/subcommand.rs L79-L83](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/subcommand.rs#L79-L83), [src/validation.rs L20-L22](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/validation.rs#L20-L22). both new ones are exported: [src/lib.rs L35-L40](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/lib.rs#L35-L40).

### raw identifiers (src/composite_surface.rs)

- pascal_case_ident did `ident.to_string()`, which for `r#type` is "r#type", so it came out "R#type" in the middle of the nested command type name, and format_ident! panics on that because it isn't a valid identifier: [src/composite_surface.rs L59-L65](https://github.com/jameshuntt/simple_impl_quote_kit/blob/61511c0fbfac6b3b3238c1c6c9988c42d6bab241/src/composite_surface.rs#L59-L65). now it unraws first, so `r#type` gives `Type`: [src/composite_surface.rs L63-L65](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/src/composite_surface.rs#L63-L65).

- this crate builds against ../liaise_proc_macro and ../simple_impl_attr_kit by path, so both jobs clone them next to it. it takes the same branch name when the sibling has one, so a change across crates gets tested together, and falls back to the sibling's default branch: [.github/workflows/ci.yml L14-L17](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L14-L17), [.github/workflows/ci.yml L29-L37](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L29-L37), [.github/workflows/ci.yml L58-L66](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L58-L66).
- publish job runs only on a push to main, only after test passes, and one at a time (`concurrency: publish`). it asks the crates.io API about this name and version: 200 means it's already up and it skips, 404 means publish, anything else fails the job: [.github/workflows/ci.yml L48-L55](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L48-L55), [.github/workflows/ci.yml L68-L77](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L68-L77).
- no stored token. it's crates.io trusted publishing: `id-token: write` plus rust-lang/crates-io-auth-action hands cargo the token: [.github/workflows/ci.yml L55](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L55-L55), [.github/workflows/ci.yml L78-L84](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L78-L84).
- publish stops if anything besides Cargo.lock differs from the commit. Cargo.lock is let through because the cloned siblings can be at another version: [.github/workflows/ci.yml L86-L91](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L86-L91).
- crates released together publish in dependency order, so when `cargo publish` fails because a dependency isn't on crates.io yet it waits 30s and retries, 30 tries max. any other publish error fails right away: [.github/workflows/ci.yml L92-L102](https://github.com/jameshuntt/simple_impl_quote_kit/blob/339df1f5db10e1fc5b3f7c23f8cf0b3d0f5e3883/.github/workflows/ci.yml#L92-L102).
